# 同步与迁移设计说明

面向后续维护者，说明「为什么这样设计」以及改动时的注意点。

## 1. 为什么不要口令

最初版本用「口令 → PBKDF2 → KEK → 包裹 DEK」，安全上更强，但有两个实际问题：

1. 每次设置都要输两遍口令，验证码工具是高频短会话产品，摩擦太大；
2. 忘记口令 = 数据永久丢失，客服无法救，差评来源。

改成**身份即密钥归属**：

- 身份：微信网关自动注入 `X-WX-OPENID`，用户零操作
- 密钥：首次使用随机生成 DEK，存本机
- 代价：设备被解锁状态下，他人可解密（已在 README 明示）

## 2. 密钥生命周期

```
首次启动 / 首次同步
  └─ vault.ensureDek()
       ├─ 读 otp_dek_hex，有则复用
       └─ 无则 wx.getRandomValues(32) 生成并落盘
```

注意：`wx.getRandomValues` 是**异步**接口，所以 `ensureDek` / `encryptVault` / `createVault`
都是 Promise。不要改成同步调用，否则会拿到 undefined。

> 历史坑：`crypto-js` 的 `WordArray.random()` 依赖原生 `crypto.getRandomValues`，
> 微信开发者工具模拟器里没有该原生模块，会抛
> `Native crypto module could not be used to get secure random number`。
> 因此本项目**不使用** `WordArray.random()`。

## 3. 同步编排

`utils/sync.js` 是唯一入口，页面与 `App.onHide` 共用：

| 函数 | 作用 |
|---|---|
| `push()` | ensureDek → 加密本地 → 上传 → 记录 `otp_last_sync_at` |
| `pull(dekHex)` | 下载 → 用 DEK 解密 → 覆盖本地 |
| `lastSyncAt()` | 读上次同步时间戳 |

并发保护：模块级 `syncing` 标志，避免 `onHide` 与手动同步撞车。

自动同步只在 `App.onHide` 触发，**不弹任何提示**；失败仅 `console.warn`，
下次进入 App 或用户手动同步时自然补上。

## 4. 迁移二维码

### 内容

```
otpmig://migrate?t=<32位hex令牌>&k=<64位hex DEK>
```

- `t`：一次性令牌，服务端存 `migrate_token` 表
- `k`：DEK 本体。**服务端不保存**，只随二维码传递

### 为什么 QR 由后端生成

小程序端没有原生二维码生成 API，自研编码器（约 300–400 行）风险高。
后端用 `qrcode` 库生成 PNG dataURI，客户端 `<image src="data:image/png;base64,...">` 直接渲染，
**无需配置 downloadFile 合法域名**。

### 时序

```
设备A                        后端                       设备B(新微信)
  │  POST /migrate/issue       │                            │
  │ ──────────────────────────▶│ 建 token(5min, 未用)         │
  │ ◀── token + qr(dataURI) ───│                            │
  │  显示二维码                 │                            │
  │                            │        扫码解析 t + k        │
  │                            │ ◀── POST /migrate/claim ────│
  │                            │ 复制 A 的 vault.data 到 B    │
  │                            │    标记 token used           │
  │                            │ ──── {code:0} ─────────────▶│
  │                            │ ◀── GET /vault ─────────────│
  │                            │ ──── 密文 ─────────────────▶│
  │                            │        用 k 解密 → 落库       │
```

### 边界条件（已实现并在测试覆盖）

| 情况 | 行为 |
|---|---|
| 令牌过期（>5min） | 410 `token expired` |
| 令牌重复使用 | 410 `token already used` |
| 源账号无数据 | 404 `no data in source account` |
| 同账号领取自己的令牌 | 400 `same account` |
| DEK 格式非法 | 400 `invalid dek` |

## 4. 回收站与软删除

删除不再直接抹掉数据，而是打时间戳进回收站：

```js
token.deletedAt = Date.now()   // 0 表示未删除
```

### 存储层约定（`utils/store.js`）

| 函数 | 语义 |
|---|---|
| `list()` | 有效账号（`deletedAt === 0`） |
| `all()` | **全部**，含回收站 —— 云同步用这个，保证回收站跨设备一致 |
| `deletedList()` | 回收站，按 `deletedAt` 倒序 |
| `remove(id)` | 软删除 |
| `removeAll()` | 批量软删除（设置页「清空全部」） |
| `restore(id)` | 从回收站恢复 |
| `purge(id)` | 彻底删除单条 |
| `purgeDeleted()` | 清空回收站 |
| `count()` / `deletedCount()` | 分别统计有效 / 回收站数量 |

`groups()` 的分组计数只统计有效账号，避免回收站数据影响列表数字。

### 日期范围筛选（`pages/recycle`）

前端按 `deletedAt` 落在区间内过滤：

| 预设 | 区间 |
|---|---|
| 今天 | 当日 00:00 → now |
| 近 7 天 | now − 7d → now |
| 近 30 天 | now − 30d → now |
| 自定义 | 起始日 00:00 → 结束日 23:59:59 |
| 全部 | 不做限制 |

时间展示用 `util.friendlyTime()`：今天 / 昨天 / N 天前 / M月D日 / 跨年补年份。

### 注意

- **回收站会占用同步体积**：`all()` 含已删除项，密文随之变大。量大时可做「超过 N 天的自动清理」。
- **`deletedAt` 参与云同步**：换机迁移后回收站原样保留，符合用户预期。
- **恢复不自动同步**：恢复后由 `App.onHide` 或手动同步补推。

## 5. 身份（微信授权）

微信 2022-10 起不再开放读取昵称的接口（`wx.getUserProfile` 返回匿名数据），
唯一合规路径是让用户主动选择一次：

| 项 | 实现 | 说明 |
|---|---|---|
| 头像 | `<button open-type="chooseAvatar">` | 回传临时路径，需压缩转 base64 |
| 昵称 | `<input type="nickname">` | 键盘上方出现「微信昵称」供选择 |

### 交互设计

- **不自动弹窗**：进入小程序不打扰用户，首页身份行显示「点击授权微信头像与昵称」作为引导
- **用户点击才弹**：点首页身份行或设置页身份行，才拉起授权引导（`components/auth-prompt`）
- **身份不可手填**：设置页「身份」行是只读展示；未授权时才可点击拉起授权
- 已授权后点击身份行无响应，避免误触覆盖已有身份

### 头像处理

优先走**云开发对象存储**，失败时退回 base64：

```
chooseAvatar → compressImage(96px, q60)
   ├─ wx.cloud.uploadFile → cloud:// fileID  → profile.avatar（约 60 字节）
   └─ 上传失败 → base64 dataURI             → profile.avatar（约 5–15 KB）
```

`<image src="{{avatar}}">` 两种格式都能渲染（cloud:// 需 `wx.cloud.init`，已具备）。

**云存储权限要求**：默认「所有用户可读，仅创建者可写」即可。若改成「仅创建者可读」，
其他设备拉取头像会 403。

历史数据处理：

`chooseAvatar` 给的是临时路径（`http://tmp/...`），重启即失效，因此：

1. `wx.compressImage({ compressedWidth: 96, quality: 60 })` 压到 96px
2. `wx.getFileSystemManager().readFile({ encoding: 'base64' })` 转 data URI
3. 存入 `profile.avatar`，随保险库加密同步

压到 96px 后 base64 约 5–15KB，对密文体积影响可接受（服务端上限 500KB）。

### 存储

- 独立键 `otp_profile_v1`：`{ nickname, avatar, authorized, updatedAt }`
- 随保险库同步（`vault.encryptCurrent` 的 payload 带 `profile`），换机后自动带过去
- 昵称上限 20 字符，超长截断；无昵称不允许提交

## 6. 改动注意事项

1. **删除账号时要同步删除云端**：目前 `clearAll` 只清本地，云端仍保留旧密文。
   若需要「彻底删除」，应加 `DELETE /api/vault` 并调用。
2. **`rev` 字段目前固定传 0**：单设备场景够用；将来做多设备冲突合并时，
   需要真的维护版本号（参考 `store.update` 的 `updatedAt`）。
3. **迁移会覆盖目标账号数据**：`claim` 直接 upsert，不做合并。已在 UI 二次确认中说明。
4. **DEK 未做设备绑定**：任何拿到 `otp_dek_hex` 的进程都能解密，
   后续若要加固，可用 `wx.startSDeviceCredential` 派生一层包裹密钥。
