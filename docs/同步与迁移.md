# 同步与迁移设计说明

面向后续维护者，说明「为什么这样设计」以及改动时的注意点。

## 1. 为什么不要口令

最初版本用「口令 → PBKDF2 → KEK → 包裹 DEK」，安全上更强，但有两个实际问题：

1. 每次设置都要输两遍口令，验证码工具是高频短会话产品，摩擦太大；
2. 忘记口令 = 数据永久丢失，客服无法救，差评来源。

改成**身份即密钥归属**：

- 身份：微信网关自动注入 `X-WX-OPENID`，用户零操作
- 密钥：首次使用随机生成 DEK，存本机
- 代价：设备被解锁状态下，他人可解密（已在 README 明示）

## 2. 密钥生命周期

```
首次启动 / 首次同步
  └─ vault.ensureDek()
       ├─ 读 otp_dek_hex，有则复用
       └─ 无则 wx.getRandomValues(32) 生成并落盘
```

注意：`wx.getRandomValues` 是**异步**接口，所以 `ensureDek` / `encryptVault` / `createVault`
都是 Promise。不要改成同步调用，否则会拿到 undefined。

> 历史坑：`crypto-js` 的 `WordArray.random()` 依赖原生 `crypto.getRandomValues`，
> 微信开发者工具模拟器里没有该原生模块，会抛
> `Native crypto module could not be used to get secure random number`。
> 因此本项目**不使用** `WordArray.random()`。

## 3. 同步编排

`utils/sync.js` 是唯一入口，页面与 `App.onHide` 共用：

| 函数 | 作用 |
|---|---|
| `push()` | ensureDek → 加密本地 → 上传 → 记录 `otp_last_sync_at` |
| `pull(dekHex)` | 下载 → 用 DEK 解密 → 覆盖本地 |
| `lastSyncAt()` | 读上次同步时间戳 |

并发保护：模块级 `syncing` 标志，避免 `onHide` 与手动同步撞车。

自动同步只在 `App.onHide` 触发，**不弹任何提示**；失败仅 `console.warn`，
下次进入 App 或用户手动同步时自然补上。

## 4. 迁移二维码

### 内容

```
otpmig://migrate?t=<32位hex令牌>&k=<64位hex DEK>
```

- `t`：一次性令牌，服务端存 `migrate_token` 表
- `k`：DEK 本体。**服务端不保存**，只随二维码传递

### 为什么 QR 由后端生成

小程序端没有原生二维码生成 API，自研编码器（约 300–400 行）风险高。
后端用 `qrcode` 库生成 PNG dataURI，客户端 `<image src="data:image/png;base64,...">` 直接渲染，
**无需配置 downloadFile 合法域名**。

### 时序

```
设备A                        后端                       设备B(新微信)
  │  POST /migrate/issue       │                            │
  │ ──────────────────────────▶│ 建 token(5min, 未用)         │
  │ ◀── token + qr(dataURI) ───│                            │
  │  显示二维码                 │                            │
  │                            │        扫码解析 t + k        │
  │                            │ ◀── POST /migrate/claim ────│
  │                            │ 复制 A 的 vault.data 到 B    │
  │                            │    标记 token used           │
  │                            │ ──── {code:0} ─────────────▶│
  │                            │ ◀── GET /vault ─────────────│
  │                            │ ──── 密文 ─────────────────▶│
  │                            │        用 k 解密 → 落库       │
```

### 边界条件（已实现并在测试覆盖）

| 情况 | 行为 |
|---|---|
| 令牌过期（>5min） | 410 `token expired` |
| 令牌重复使用 | 410 `token already used` |
| 源账号无数据 | 404 `no data in source account` |
| 同账号领取自己的令牌 | 400 `same account` |
| DEK 格式非法 | 400 `invalid dek` |

## 5. 改动注意事项

1. **删除账号时要同步删除云端**：目前 `clearAll` 只清本地，云端仍保留旧密文。
   若需要「彻底删除」，应加 `DELETE /api/vault` 并调用。
2. **`rev` 字段目前固定传 0**：单设备场景够用；将来做多设备冲突合并时，
   需要真的维护版本号（参考 `store.update` 的 `updatedAt`）。
3. **迁移会覆盖目标账号数据**：`claim` 直接 upsert，不做合并。已在 UI 二次确认中说明。
4. **DEK 未做设备绑定**：任何拿到 `otp_dek_hex` 的进程都能解密，
   后续若要加固，可用 `wx.startSDeviceCredential` 派生一层包裹密钥。
