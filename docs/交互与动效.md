# 交互与动效规范

## 一、动效令牌（`app.wxss`）

所有动画统一引用这几个变量，改一处即可全局调整节奏：

```css
--ease:    cubic-bezier(0.22, 0.8, 0.2, 1);   /* 常规进出 */
--ease-out: cubic-bezier(0.16, 1, 0.3, 1);    /* 强出场（翻牌） */
--spring:  cubic-bezier(0.34, 1.32, 0.64, 1); /* 弹性（复制成功） */
--dur-1: 0.16s;   /* 按压反馈 */
--dur-2: 0.26s;   /* 抽屉、弹窗 */
--dur-3: 0.4s;    /* 入场、翻牌 */
```

## 二、动画清单

| 动画 | 用途 | 时长/曲线 |
|---|---|---|
| `rise` | 列表条目入场（stagger 40ms 递增，封顶 280ms） | `--dur-3` / `--ease` |
| `float-in` | 空态、片段浮入 | `--dur-3` / `--ease` |
| `flip` | 验证码到周期后的翻牌（绕顶边 3D） | `--dur-3` / `--ease-out` |
| `pop` | 复制成功的对勾弹出 | `--dur-2` / `--spring` |
| `sheet-up` | 底部抽屉（移动分组、选择迁入分组） | `--dur-2` / `--ease` |
| `dialog-in` | 居中弹窗（迁移二维码） | `--dur-2` / `--ease` |
| `fade` | 遮罩淡入 | 0.2s |
| `tab-in` | 分组 tab 下划线展开（scaleX） | `--dur-2` / `--ease` |
| `breathe` | 分页加载三点呼吸 | 1.1s 循环 |
| `warn-pulse` | 剩余秒数 ≤5 时数字呼吸提示 | 1.6s 循环 |

### 设计原则

1. **一次编排优于多处零散**：入场只在列表首次渲染时错开，不做逐卡 hover 动画。
2. **反馈即因果**：只有用户动作（复制、切换、下拉）才触发动画，不主动播放。
3. **动效不阻塞**：`will-change: transform, opacity` 只加在列表卡片上；不做 layout 属性动画（宽高、top/left），一律用 `transform`。
4. **危险状态常驻提醒**：剩余 ≤5 秒时数字呼吸 + 变红，属于信息而非装饰。

## 三、按压反馈

统一用 `:active` + `transform: scale(0.97~0.99)`，不改变布局：

| 元素 | 缩放 | 附加 |
|---|---|---|
| 列表卡片 `.token` | 0.988 | 透明度 0.96 |
| 圆形图标按钮 `.act` | 0.9 | 颜色转品牌蓝 |
| 复制按钮 `.copy` | 0.94（弹性） | 背景切换 |
| FAB | 0.955 | 展开时旋转 45° |
| 底部主按钮 | 0.985 | — |

## 四、分页与下拉刷新

### 分页

```
pageSize  = 20
page      = 1..n
hasMore   = visible.length < filtered.length
```

- `compute()` 先把过滤后的完整列表算到 `this._filtered`，再由 `applySlice()` 按 `page * pageSize` 切片塞进 `data.list`
- 每秒的 tick 只重算验证码，不重置页码
- 切换分组 / 搜索 / 清除搜索 → `page` 归 1
- 触底加载：`onReachBottom` → `page + 1` → 重新切片，中间留 280ms 让「正在加载」可见

### 下拉刷新

- `index.json` 开启 `enablePullDownRefresh`
- `onPullDownRefresh` 重新读 `store.list()`（回收站恢复、其他页面改动都能立刻反映），重置 `page = 1`，420ms 后 `wx.stopPullDownRefresh()`
- **不触发云端拉取**：云同步仍由「退出自动上传 / 设置页手动同步」负责，避免下拉误覆盖本地未上传的改动

## 五、下一码（预读）

主码下方以 24rpx 小字显示「下一码」，与主码同源同周期，**当前码到期后它立刻成为主码**。

- 计算：`totp.generateNext(token, now)`
  - TOTP → `counter + 1` 的码（等价于 `now + period` 时刻的码）
  - HOTP → `counter + 1` 的码
- 只在**已显示**状态产出；隐藏态不计算、不渲染（避免泄露）
- 每秒随 tick 重算，跨周期时自动更替
- 主码进入 ≤5s 告警时，下一码同步转为浅红，形成"即将交接"的视觉暗示

## 六、空态

分组下无账号时不再显示「＋」图标——右下角悬浮按钮已是唯一添加入口，
空态只保留标题 + 一句说明，减少重复的操作暗示。

## 七、页面切换

微信小程序的页面转场由系统控制，`wx.navigateTo` / `wx.navigateBack` **不支持自定义动画参数**
（官方 typings 的 `NavigateToOption` / `NavigateBackOption` 中均无 `animation` 字段）。
因此转场优化做在**内容层**：

| 类 | 作用 | 参数 |
|---|---|---|
| `.page-enter` | 页面根容器落定（opacity + 10rpx 上移） | `--dur-3` / `--ease-out` |
| `.nav-enter` | 自定义导航栏从上方轻落 | `--dur-2` / `--ease-out` |
| `.enter-1` | 第二层（搜索框、筛选条） | 延迟 50ms |
| `.enter-2` | 第三层（分组 tab） | 延迟 100ms |
| `.enter-3` | 第四层（首个卡片 / 警示条） | 延迟 150ms |

关键点：

1. **位移量刻意很小（8–10rpx）**。系统转场本身就是几十 px 的横滑，内容再大幅移动会显得"抖两下"；
   小位移只制造"内容落定"的错觉，与原生转场叠加后更自然。
2. **用 `--ease-out`（急停曲线）**，让动画在前 1/3 就基本到位，避免看起来"慢半拍"。
3. **动画只在页面首次挂载时播放**。返回上一页（页面实例仍在栈中）不会重播，符合预期。
4. **切换分组时**列表整体轻落一次（`.list.is-switch` + `float-in`，280ms 后自动摘除类），
   用 280ms 的定时器而非 `animationend`，避免小程序自定义组件内事件不触发的兼容问题。

## 八、加载态

任何可能等待超过 ~300ms 的操作都显示加载遮罩（`components/loading`），避免"点了没反应"。

| 触发 | 文案 |
|---|---|
| 设置 → 立即同步 | 正在同步 |
| 设置 → 迁移到其他微信号 | 正在生成二维码 |
| 设置 → 从二维码迁移（接收） | 正在接收 |
| 设置 → 清空全部 | 正在移入回收站 |
| 回收站 → 清空回收站 | 正在清空 |

组件结构：半透明遮罩 + 白卡片 + 旋转环（`border` 单边着色 + `spin` 0.72s 线性循环）+ 文案。
挂载时用 `dialog-in` 放大入场，避免生硬弹出。

## 九、注意事项

- **居中弹窗不要用 `transform: translate(-50%, -50%)`**：它会和入场动画里的 `transform: scale()` 互相覆盖，
  导致弹窗偏移一半高度（迁移二维码曾出现此问题）。正确做法是用 flex 居中父容器，子元素只做缩放动画。
- 主码进入 ≤5 秒告警态时，仅主码变红；**「下一码」始终保持灰色**，避免读者误以为下一码也失效。

1. 分页只影响渲染，**不影响同步**——同步始终使用 `store.all()` 的完整数据。
2. `setData` 每秒执行一次，因此 `applySlice` 必须保持纯函数、无副作用。
3. 列表使用 `wx:key="id"`，切片变化时未变化的条目会复用节点，不会重播入场动画。
4. 新增动画请复用上表令牌，不要写死秒数，否则调节奏时要改多处。
